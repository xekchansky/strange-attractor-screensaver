# AGENTS.md — working notes for contributors and coding agents

This file is the entry point for anyone (human or automated) changing this
repository. Read it before the first edit.

## What this project is

A macOS screen saver that renders strange attractors: a chaotic trajectory is
integrated in real time, drawn as a fading polyline, and orbited by the camera.
Attractors are described entirely by data, so adding one does not require code.

- **Language:** Swift 6, macOS 13+ deployment target.
- **Frameworks:** AppKit, SceneKit, QuartzCore, ScreenSaver, Metal.
- **Dependencies:** none beyond Apple frameworks and `swift-testing` (tests
  only). Do not add a package without discussing it first.

## Repository layout

| Path | Contents |
| --- | --- |
| `Core/` | `AttractorCore`: pure, UI-free SPM module — data model, formula parser, RK4 solver, engine, trace buffer, randomizer, health monitor. |
| `Render/` | `AttractorRender`: SceneKit scene, orbiting camera, gradient trail renderer, formula overlay. |
| `Demo/` | `AttractorDemo`: standalone AppKit app with CLI flags and PNG capture. |
| `Host/` | Screen saver targets: classic `.saver` bundle and the `.appex` variant, generated by xcodegen from `Host/project.yml`. |
| `docs/` | Capture script and the images used by the READMEs. |
| `.serena/memories/` | Design notes and investigation history. Read-only background; update when a contract changes. |

## Build and test

Core is the testable heart of the project and builds without Xcode:

```bash
cd Core
swift test      # unit tests
swift build     # compile check
```

Render and Demo build as SPM packages but need the macOS SDK:

```bash
cd Demo && swift build
```

The screen saver project is generated, never edited by hand:

```bash
cd Host
xcodegen generate
xcodebuild -project AttractorHost.xcodeproj -scheme AttractorSaver \
  -configuration Release -derivedDataPath /tmp/host-dd build
```

Capture (`--screenshot` / `--record`) and the screen saver itself need a real
GUI session: SceneKit wants a laid-out window and Metal, so these do not work
over SSH or in a background launch context.

## Architecture rules

1. **Keep logic in `Core`.** `AttractorCore` must not import AppKit, SceneKit or
   any other UI framework. Rendering and hosting live in `Render`/`Host`.
2. **Attractors are data.** Formulas, parameter ranges and simulation
   hyperparameters live in `Core/Sources/AttractorCore/Resources/attractors.json`.
   Never hard-code an attractor or its parameters in Swift.
3. **Formulas are strings.** They are parsed by the recursive-descent
   `FormulaParser` (not `NSExpression`, which cannot call `sin`/`abs`). If you
   add a function, add it to `Expression.supportedFunctions` as well — catalog
   validation rejects anything outside that list.
4. **Explicit types over tuples.** Use `State`, `SimulationSettings`,
   `AttractorSelection`, `MinMax` instead of bare numbers or tuples.
5. **Deterministic numerics.** `ODESolver` (RK4) is the contract. Do not change
   the stepping scheme or default step sizes without re-checking known orbits
   (Lorenz r=28, Chua, Aizawa) and the health-monitor tests.
6. **The trace is a ring buffer.** `TraceBuffer` keeps a fixed capacity and
   exposes it as a `RandomAccessCollection`; do not reintroduce `removeFirst()`
   on a growing array.
7. **Tests are part of the contract.** Every public symbol gets a unit test.
   Degenerate runs (fixed points, limit cycles, non-finite states) are covered
   by `SimulationHealthMonitorTests`; keep those green.

## Definition of done

- `swift test` in `Core` is green, and `swift build` produces no errors.
- No dead code, no leftover debug prints, no unused files.
- Comments and identifiers in English; the Russian README is kept in sync with
  the English one when user-facing behaviour changes.
- If a public contract changed, update the relevant `.serena/memories/` note.
- One atomic commit with a message in English.
