# AGENTS.md — working notes for contributors and coding agents

This file is the entry point for anyone (human or automated) changing this
repository. Read it before the first edit.

## What this project is

A strange-attractor screen saver for macOS, Windows, Linux and Android, plus a
browser demo. A chaotic trajectory is integrated in real time, drawn as a
fading gradient ribbon, and orbited by the camera. Attractors are described
entirely by data, so adding one does not require code.

One Rust engine renders every target through `wgpu`; the shells only own the
platform surface and input. The Swift implementation that the port was verified
against is archived at the git tag `swift-oracle` and is no longer built.

- **Language:** Rust (edition 2024) for everything except the macOS host view
  and the Android shell.
- **Platforms:** macOS 13+ (`.saver`), Windows 10+ (`.scr`), Linux
  (xscreensaver hack and a fullscreen runner), Android 8+ (live wallpaper),
  any modern browser (WebGPU with a WebGL2 fallback).
- **Dependencies:** `wgpu`, `glyphon`, `serde`, `winit`/`x11-dl`/`windows-sys`
  in the shells, `wasm-bindgen` in the web crate. Do not add a package without
  discussing it first.

## Build and test

The workspace check is the everyday gate:

```bash
cd rust
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

GPU-backed tests skip with a printed reason when no adapter is available; on a
desktop with a working GPU a bare `cargo test --workspace` runs them. The
pipeline tests work everywhere through wgpu's `noop` backend.

Platform targets need their standard library and, for Android, the NDK:

```bash
cd rust
cargo clippy -p attractor-linux-saver -p attractor-gpu \
  --target x86_64-unknown-linux-gnu --all-targets -- -D warnings
cargo clippy -p attractor-windows-saver -p attractor-gpu \
  --target x86_64-pc-windows-gnu --all-targets -- -D warnings
cargo clippy -p attractor-ffi -p attractor-gpu \
  --target aarch64-linux-android --all-targets -- -D warnings
cargo clippy -p attractor-wasm --target wasm32-unknown-unknown --all-targets -- -D warnings
```

The macOS bundle is generated, never edited by hand:

```bash
cd Host && xcodegen generate
cd .. && ./scripts/package_release.sh "$TMPDIR/dist"
```

Capture (`--screenshot` / `--record`) and the screen savers themselves need a
real GPU and a GUI session; they do not work over SSH or in a background
launch context.

## Architecture rules

1. **Keep logic in `attractor-core`.** It must not depend on `wgpu`, `winit`,
   `wasm-bindgen` or any platform crate. `attractor-view` stays GPU-free and
   deterministic.
2. **Attractors are data.** Formulas, parameter ranges and simulation
   hyperparameters live in `data/attractors.json`. Never hard-code an
   attractor or its parameters in Rust, Kotlin or JavaScript.
3. **Formulas are strings.** They are parsed by the recursive-descent
   `FormulaParser`. A new function must be added to
   `Expression::supportedFunctions` as well, or catalog validation rejects it.
4. **Explicit types over tuples.** Use `State`, `SimulationSettings`,
   `AttractorSelection`, `MinMax` instead of bare numbers or tuples.
5. **Deterministic numerics.** `ODESolver` (RK4) is the contract. Do not change
   the stepping scheme or default step sizes without re-checking known orbits
   (Lorenz r=28, Chua, Aizawa) and the health-monitor tests.
6. **The trace is a ring buffer.** `TraceBuffer` keeps a fixed capacity and
   exposes it as a collection; do not reintroduce `removeFirst()` on a growing
   array.
7. **Fixtures are immutable.** The golden files under
   `rust/crates/*/tests/fixtures/` were generated from the Swift oracle at tag
   `swift-oracle`. Regenerate only when the numerical contract changes, by
   checking out that tag; the Rust tests never need a live Swift toolchain.
8. **Tests are part of the contract.** Every public symbol gets a unit test.
   Degenerate runs (fixed points, limit cycles, non-finite states) are covered
   by `tests/simulation_health_monitor.rs`; keep those green.

## Definition of done

- `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`
  and `cargo test --workspace` are green in `rust/`.
- The Apple, Windows, Linux, Android and wasm targets still compile (the
  cross-clippy commands above, or CI).
- No dead code, no leftover debug prints, no unused files.
- Comments and identifiers in English; the Russian README is kept in sync with
  the English one when user-facing behaviour changes.
- `rust/STATUS.md` records the iteration, its rulings and any deferred work.
- One atomic commit with a message in English.
