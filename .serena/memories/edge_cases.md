# Крайние случаи (M6)

Направление M6: защита от зависаний и чёрного экрана. Упаковка — отдельная сессия.

## Итерация 1 (2026-11-03): устойчивость к стойлам и битому конфигу

### Зависание после сна/остановки процесса
`SimulationScene.tick` брал `dt = now - lastTime` без ограничения и считал `Int(accumulated / stepSize)`. После sleep/wake `dt` — секунды/минуты, значит десятки тысяч шагов за один кадр; при `stepSize = 0` — `Int(infinity)` и краш.

Введён чисто ядерный `SimulationStepScheduler` (`Core/.../SimulationStepScheduler.swift`):
- `dt` ограничивается `maximumFrameInterval` (по умолчанию 0.1 с);
- число шагов за кадр ограничено `maximumStepsPerFrame` (4096) — страховка на случай крошечного `stepSize`;
- при упоре в cap накопленный «долг» сбрасывается, а не переносится: после сна не нужно догонять пропущенное время;
- нефинитные/неположительные `dt`, `stepSize`, `simulationSpeed` дают 0 шагов вместо краша.

`SimulationScene` клампит `dt` тем же `maximumFrameInterval` и до камеры/цвета, чтобы после сна не прыгали орбита и градиент.

Итог: максимальная работа после стойла — `speed * 0.1 / stepSize` шагов (у каталога ≈ 75), а не десятки тысяч. `O(n)`-сдвиг `trace.removeFirst()` на каждом шаге остаётся, но ограничен.

### Битый конфиг не должен гасить заставку
`AttractorCatalog.validate(_:)` / `bundledValidation()` проверяют каждый дескриптор и **отбрасывают только плохие**, возвращая `AttractorCatalogValidation` (`valid` + `issues`):
- пустой каталог;
- пустой/дублирующийся `id`;
- диапазоны: конечность, `min <= max`; `stepSize > 0`, `simulationSpeed > 0`, `cameraRotationSpeed/trailColorSpeed >= 0`, `trailLength >= 2`;
- параметры: непустые, уникальные, не совпадают с `x/y/z`;
- формулы: парсятся, ссылаются только на `x/y/z` + объявленные параметры. Для этого у `Expression` появилось `referencedVariables`.

Хост (`ScreensaverView.startSimulation`) и демо (`main.swift`) используют `bundledValidation()`: issues пишутся в лог/`stderr`, выбор идёт из `valid`. Пустой `valid` → запись в лог и без краша (показывать нечего только при полностью сломанном бандле).

### Ошибка вычисления формулы больше не «замораживает» кадр
Было: `guard let advanced = try? engine.advance() else { continue }` — при доменной ошибке (`sqrt`/`ln` от недопустимого значения) шаги молча пропускались, трейс навсегда замирал на последней точке, монитор здоровья ничего не видел (он получает только успешные состояния).

Теперь ошибка `engine.advance()` → `requestRestart(reason:)` (общий путь с health-monitor): сцена останавливается, хост делает новый случайный выбор. В демо с явными аргументами (`healthMonitor == nil`) перевыбор по-прежнему отключён — остаётся застывший кадр и лог, это режим отладки.

## Осталось по списку крайних случаев
1. Restart storm: лимит/backoff при частых перезапусках, фолбэк на заведомо исправный аттрактор.
2. Мультимониторность/хотплаг: не проверено, не рвётся ли показ через `viewDidMoveToSuperview == nil`.
3. Демо-CLI: `--step 0`, `--trail-length < 2`, отрицательные скорости — сейчас принимаются и приводят к статике/пустому трейлу.
4. Упаковка — отдельная сессия.
