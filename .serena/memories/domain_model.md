# Доменная модель и глоссарий: strange-attractor-screensaver

## Бизнес-сущности

### Аттрактор (Attractor)
Множество точек (траектория), к которому стремится детерминированная динамическая система. В проекте — описывается системой ОДУ и визуализируется.
- **Аттрактор Лоренца:** `x'=a(y-x)`, `y'=x(r-z)-y`, `z'=xy-bz` (классика: r=28).
- **Аттрактор Рёсслера:** `x'=-y-z`, `y'=x+ay`, `z'=b+z(x-c)` (a,b,c>0).
- **Аттрактор Томаса:** `x'=sin(y)-bx`, `y'=sin(z)-by`, `z'=sin(x)-bz` (обычно b=0.2081).
- **Аттрактор Чена:** `x'=a(y-x)`, `y'=(c-a)x-xz+cy`, `z'=xy-bz` (классика: a=35, b=3, c=28).
- **Аттрактор Айзавы:** `x'=(z-b)x-dy`, `y'=dx+(z-b)y`, `z'=c+az-z³/3-(x²+y²)(1+ez)+fzx³` (классика: a=0.95, b=0.7, c=0.6, d=3.5, e=0.25, f=0.1). Формулы используют `^` (степень): `(z ^ 3) / 3`, `(x ^ 2 + y ^ 2)`, `(x ^ 3)`.
- **Аттрактор Лу (bü):** `x'=a(y-x)`, `y'=-xz+cy`, `z'=xy-bz` (классика: a=36, b=3, c=20).
- **Аттрактор Чуа:** кусочно-линейный двойной скролл: `x'=a(y-x-f)`, `y'=x-y+z`, `z'=-b y`, `f=m1 x+0.5(m0-m1)(|x+1|-|x-1|)` — выражен функциями `abs` (парсер их уже поддерживает). **Рабочие параметры:** a=9.5–10.5, b=14–15, m0=-0.55…-0.45, m1=0.2–0.3. Двойной скролл спонтанно растёт из малого старта; «литературные» m0≈-1/7/m1≈2/7 дают асимптотически устойчивую точку (0,0,0) и «залипание» у нуля — не использовать.
- **Аттракторы Спротта A–C:** простейшие хаотические потоки, параметры фиксированы (в конфиге — пустой `parameters`, коэффициенты константами). D–J **исключены**: бассейны притяжения малы, при случайных стартах расходились (проверено 300 стартов × 50k шагов: D — 154/200, E — улетает, F — 159/300, G — 53/300, H — 61–98/300, I — 94/200, J — все). K–S пока не добавлены (см. `mem:planned_attractors`).
- **Аттрактор Халворсена:** `x'=-a·x-4y-4z-y²`, циклические ротации для y/z; a≈1.4 (диапазон 1.25–1.45). Равновесие в 0 — седло: диагональный старт (x=y=z) скатывается к нулю, поэтому важен недиагональный initial state.
- **Аттрактор Рабиновича — Фабриканта:** `x'=y(z-1+x²)+g·x`, `y'=x(3z+1-x²)+g·y`, `z'=-2z(a+xy)`; канонический хаос a=0.14, g=0.1. **Исключён из каталога:** бассейн притяжения ничтожен — ~50% случайных стартов (±0.5 и даже ±0.1) расходятся к ∞. Канон a=1.1/g=0.87 тоже расходится. Вернуть только с детерминированным стартом вблизи аттрактора.
- **Аттрактор Мура — Шпигеля:** 3D-представление осциллятора 2-го порядка: `x'=y`, `y'=z`, `z'=-z-(T-R+R x²)y-T·x` (форма стабильна; альтернативная вики-форма `-z-x-Ry+Tx-x³` расходится). Рабочий хаос T≈8–16, R≈16–24.
- Добавлены 2026-10-01 в каталог `attractors.json` (5 → 12 после исключения нестабильных Sprott D–J и R–F) и в README; см. `mem:planned_attractors` для запланированных.
- Расширяется через конфиг-файл без изменения кода.

### Descriptor (AttractorDescriptor)
Мета-описание аттрактора в `attractors.json`: id, имя, формулы, параметры, гиперпараметры. Загружается через Codable.

### Параметр (Parameter)
Коэффициент системы (a, b, c, r...) с диапазоном `[min, max]`. При запуске выбирается случайно из диапазона.

### Гиперпараметры симуляции (SimulationHyperparameters)
Настройки визуализации/симуляции (не физика системы): скорость симуляции, длина шага (точность интегрирования), скорость вращения камеры, скорость изменения цвета следа, длина следа, и т.п. Выбираются случайно из диапазонов; для отладки задаются вручную.

### Состояние (State)
Текущий вектор (x, y, z) точки на траектории.

### Симуляция / Аттрактор-движок (AttractorEngine)
Поток, который шагает динамическую систему численным интегрированием (RK4/Euler) и выдаёт последовательность точек.

### Траектория / След (Trace)
Буфер последних точек, отображаемый рендером как линия/облако с цветовой градацией.

### Файл конфигурации (attractors.json)
Файл, описывающий аттракторы выражениями (формулы), диапазоны параметров и диапазоны гиперпараметров.

## Глоссарий
- **ОДУ / дифференциальная формула** — система обыкновенных дифференциальных уравнений, задающая динамику аттрактора.
- **NSExpression** — Apple-парсер арифметических выражений, используемый для разбора строк формул.
- **Численное интегрирование** — приближённое решение ОДУ (метод RK4, метод Эйлера).
- **.appex** — пакет app-extension (современный формат скринсейвера).
- **ScreenSaverView** — главный класс скринсейвера (в новом формате `.appex`).
- **SceneKit / SCNView** — фреймворк и view для 3D-рендеринга.
- **Randomizer** — случайный выбор аттрактора, параметров и гиперпараметров при запуске.
- **DebugConfig** — ручной ввод параметров для отладки.

### Сторожевой механизм (SimulationHealthMonitor)
Чистый ядерный компонент, который получает по одному состоянию на шаг интегрирования и решает, «здоров ли» запуск. Сбои: `nonFinite` (NaN/inf), `diverged` (координата > 1e6), `collapsed` (размах траектории за окно меньше порога — точка равновесия или крошечное кольцо), `periodic` (устойчивый цикл любого размера; определяется статистически — близкий возврат по окну до 2048 состояний с резким провалом на полулаге, вердикт должен держаться 4096 шагов). При сбое симуляция полностью перевыбирается. Пороги и расписание проверок — `SimulationHealthThresholds`; дорогая периодическая проверка идёт раз в 512 шагов. Точный повтор участка не используется: у предельных циклов период обычно нецелый в шагах.

## Связи
- Один **Descriptor** → конкретный **AttractorModel** (состояние + параметры + формулы).
- **AttractorEngine** использует **ODESolver** для перехода между состояниями.
- **Randomizer/DebugConfig** → задают **параметры** и **гиперпараметры**.
- **TraceRenderer** читает буфер **Trace** из движка и отображает его в **SCNView**.
