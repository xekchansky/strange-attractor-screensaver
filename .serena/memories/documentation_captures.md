# Документационные съёмки (M6)

Скриншоты и hero-гифка снимаются демо-приложением через `docs/capture_all.sh`
(нужен GUI-сеанс: Metal/WindowServer). Скрипт — единственный источник истины
для набора ассетов; README ссылается на него.

## Что фиксируется для воспроизводимости
- **Параметры** — `-p name=value`. Любой `-p` переводит выбор в `DebugConfig`:
  не указанные параметры и гиперпараметры берутся как середины диапазонов,
  `colorMode` = `.trail` (радуга; без `-p` режим цвета выбирается случайно — так
  один из первых скриншотов Rössler вышел чёрно-белым `.age`).
- **Шаг** — `--step`, если середина диапазона численно вырождена (Aizawa: 0.007
  даёт периодическую орбиту, рабочий шаг 0.008 / hero 0.002).
- **Начальное состояние** — `--initial-state x,y,z`. Нужен Thomas: старт из
  середины диапазона (≈0,0,0) попадает в бассейн неподвижной точки при
  `b ∈ [0.17, 0.206]`; рабочий набор — `b=0.208186`, старт `0.6,0.6,-0.86`.
- **Угол камеры** — `--cam-azimuth <deg>` / `--cam-elevation <deg>`
  (`CameraController(azimuth:elevation:)` → `SimulationScene(cameraAzimuth:…)`).
  Без них азимут случайный, высота π/5 (36°).
- **Скорости** — `--cam-speed 0` и `--trail-color-speed 0` для скриншотов:
  кадр снимается после 90 тиков «усадки», иначе камера успевает уехать ~20°,
  а градиент — прокрутиться.
- **Длина трейла** — `--trail-length`; Sprott 20000, Chua 12000 (при шаге
  0.0006 дефолтные 2000–8000 покрывают лишь часть двойного скролла).
- **Warm-up** — `--warmup-steps` (по умолчанию 60000; Chua 200000, hero 0).

| Аттрактор | Аргументы |

| thomas | `-p b=0.19 --initial-state 0.6,0.6,-0.86 --trail-length 20000 --cam-azimuth 0 --cam-elevation 10` |
| chen | `-p a=38 -p b=3 -p c=28 --cam-azimuth 120 --cam-elevation 25` |
| lu | `-p a=36 -p b=3 -p c=20 --cam-azimuth 20 --cam-elevation 20` |
| chua | `-p alpha=15.6 -p beta=25.6 -p m0=-1.143 -p m1=-0.714 --trail-length 24000 --warmup-steps 200000 --cam-azimuth 90 --cam-elevation 65` |
| moore_spiegel | `-p R=250 -p T=10 --step 0.003 --trail-length 20000 --cam-azimuth 90 --cam-elevation 12` |

(всем — плюс `--cam-speed 0 --trail-color-speed 0`). Здоровье проверено
численно (`SimulationHealthMonitor`, 60k–200k шагов RK4): все шесть healthy.

**Как выбирать угол без GPU:** угол можно подобрать офскрин —
прогнать рецепт пробным пакетом (SPM-цель, линкующая локальный `Core`),
выгрузить видимый трейл в CSV и отрисовать его ортографической/перспективной
проекцией с той же математикой камеры (`distance = max(radius * 2.1, 2)`,
fov 60°, up = +y). Совпадает с реальным кадром достаточно точно, чтобы
отличить удачный ракурс от неудачного.

Ориентиры по геометрии для выбора углов: у Chua двойной скролл лежит в
плоскости x–z и тонок по y, поэтому вид почти сверху (`--cam-elevation 85`);
в рендере вертикаль экрана — это ось y состояния.

## Hero-гифка
Aizawa, канонические параметры, `--step 0.002 --speed 0.7`, запись 80 с при
`--frame-stride 1` → 2400 кадров, 640px, GIF 50 fps (2 cs задержка — минимум,
который браузеры соблюдают), 48 с цикла. Анимированный WebP не использован:
4:2:0 + межкадровые дельты дают бледные вертикальные полосы на тонких линиях,
и GitHub не анимирует WebP в README.
