# Правила разработки проекта: strange-attractor-screensaver

> Стек утверждён: `.appex`, SceneKit, собственный парсер формул, Swift, без внешних зависимостей.
> Среда разработки: macOS 26 arm64; установлены Command Line Tools (swift/SPM), полного Xcode нет → сборка `.appex` выполняется в Xcode отдельно.

## Локальный запуск

### Чистое ядро (SPM) — работает из папки проекта
Прогон тестов (ядро): см. `mem:build_environment` — там точная рабочая команда с литеральным путём к `usr/lib` (не через `LIBCACHE=... swift` — в этой среде инлайн-префикс не подставляется).
Выборочно: `swift test --filter <Symbol>`.

SPM работает в этой среде — основная проверка логики происходит именно здесь, без Xcode.

### Визуализация (демо-приложение, AppKit + SceneKit)
- Отдельный SPM-пакет `Demo/` (исполняемый `AttractorDemo`), зависящий от `Core/` по локальному пути. Собирается/запускается из CLI: `cd Demo && swift build` / `swift run AttractorDemo`.
- AppKit/SceneKit успешно импортируются из CLI-сdk (проверено 2026-09-29): Xcode для демо НЕ нужен (нужен только для хост-`.appex` в M5). Правки в `Demo/` — нативными инструментами (см. `mem:architecture`, LSP недоступен).
- Аргументы: `--attractor <id>`, `--param name=value` (или голые `name=value` токены); без аргументов — случайный выбор (Randomizer).

### Хост-скринсейвер (`.appex`) — требует Xcode
- Таргет «Screen Saver» (`.appex`), главный класс `ScreenSaverView`.
- В этой среде без Xcode эта часть собирается только на машине с Xcode.

## Тестирование (стратегия)

Правило: **ядро тестируется автоматически, рендер/хост — вручную.**

1. **Юнит-тесты ядра (SPM, `swift test`, Swift Testing)** — основной уровень:
   - Декодинг конфига: валидная фикстура, отсутствующие поля, битые числа, неизвестные ключи.
   - Парсер формул: приоритеты операторов, скобки, унарный минус, правоассоциативный `^`, подстановка переменных, тригонометрия, синтаксические ошибки.
   - Численное интегрирование: RK4 против Euler, точность порядка, эталонные траектории (Лоренц и т.п.).
   - Модель/движок: `rate(of:)` по эталону, ограничение буфера трассы, конечность значений.
2. **Визуальная проверка** (демо-приложение, вручную): картинка траектории, вращение камеры, смена цвета следа, формулы/параметры в углу.
3. **Смоук на реальном скринсейвере** (`.appex`, вручную): Preview и Test в System Settings, старт/остановка, случайность запусков.

Перед коммитом обязателен зелёный `swift test` (для шагов, затрагивающих ядро).

## Код-стайл и конвенции

- **Язык кода:** Swift. Идентификаторы и комментарии в коде — на английском (`state`, `step`, `AttractorEngine`).
- **Документация и общение:** README, memories — на русском.
- **Модульность:** чистое ядро (SPM) отдельно от UI-рендера и хост-оболочки. Логика не зависит от рендера → тестируемость.
- **Тесты рядом с кодом:** для каждого публичного символа ядра есть покрытие.
- **Публичные API** — с `///`-комментариями (назначение, параметры).
- **Зависимости:** не добавляем внешние без необходимости; предпочтение Apple-фреймворкам.
- **Naming:** типы — существительные (`ODESolver`, `TraceRenderer`), функции/методы — глаголы (`step`, `select`, `render`).

## Актуальные ограничения среды (M2, зафиксировано 2026-09-29)

- **LSP недоступен** (`get_current_config` → `Active language servers: .`; переактивация проекта не помогает). Следствие: символьные/файловые write-инструменты на существующих файлах через Serena (`replace_content`, `replace_in_files`, `replace_symbol_body`, ...) возвращают `No language servers available in the manager`.
  - Новые файлы создаём `create_text_file` (не требует LSP) — работает.
  - Правку существующих не-Swift файлов (README, `Package.swift`, `attractors.json`) делаем точечно нативным `Edit` с точным совпадением (не переписываем целиком, не стираем соседний код), помечая это в резюме пользователю.
  - Правку существующих `.swift` файлов лучше отложить/минимизировать; если нужна — минимальный нативный Edit с осторожностью. Как только LSP появится — вернуться к символьным инструментам Serena.
- **Тригонометрия в формулах — РЕШЕНО (M2).** Стандартный `NSExpression` НЕ имеет `sin/cos/tan`. Вместо него реализован собственный парсер `FormulaParser` (рекурсивный спуск) → AST `Expression` с функциями `sin/cos/tan/sqrt/abs/exp/ln/log`. Решение утверждено пользователем. Обновляется только ядро; конфиг `attractors.json` не меняется (формулы остаются строками).

## Git-практика

- Атомарные коммиты: один логический шаг = один коммит, сообщение по смыслу (тип: описание), на английском.
- Каждый майлстоун завершается зелёными тестами и (если нужно) отдельным коммитом.
- Работа ведётся в ветках по этапам, мёрдж в `main` после зелёных тестов.
- `swift test` перед коммитом ядра.

## Итеративный чеклист (майлстоуны)

Принцип: **маленькие итерации**, каждый шаг завершается работающим состоянием и зелёными тестами. Порядок выстроен от тестируемого ядра к Xcode-хвостам.

- **M0 — Фундамент.** ✅ SPM-пакет ядра; тесты поднимаются (`swift test` зелёный); git-практика.
- **M1 — Модель данных и конфиг.** ✅ `AttractorDescriptor`, `Parameter`, `MinMax`, `SimulationHyperparameters` (Codable); `attractors.json` (Лоренц/Рёсслер/Томас) как ресурс; `AttractorCatalog` loader; тесты декодинга.
- **M2 — Математическое ядро.** ✅ `State`/`Derivatives`, `FormulaParser`+`Expression` (свой парсер, тригонометрия), `AttractorModel` (`rate(of:)`), `ODESolver` (RK4+Euler), `AttractorEngine` (поток точек + кольцевой буфер `trace`); численные тесты.
- **M3 — Выбор.** ✅ `SplitMix64` (seedable ГПСЧ), `SimulationSettings`, `AttractorSelection`, `Randomizer` (инжектируемый RNG), `DebugConfig` (фабрика с дефолтами-серединами); тесты диапазонов и seed; раздел выбор включает начальное состояние (`StateRange` + `initialState`); `swift test` зелёный (48 тестов, 9 сьюит).
- **M4 — Визуализация в демо-приложении.** ✅ SPM-пакет `Demo/` (исполняемый `AttractorDemo`, AppKit+SceneKit): `TraceRenderer` (полилиния+градиент), `CameraController` (орбита+автокадрирование), `SimulationScene` (движок+таймер+оверлей формул/параметров), CLI `--attractor`/`--param` или случайный выбор; `swift build` в `Demo/`; рендер проверяется вручную.
- **M5 — Хост `.appex`.** Таргет Screen Saver, `ScreenSaverView`, подключение ядра, вывод формул/параметров в углу; проверка в System Settings.
- **M6 — Полировка.** Производительность, крайние случаи (деление на ноль/нестабильные параметры), упаковка и документация.

Статус отмечаем в README (раздел «Дорожная карта»): ⏳ / в работе / ✅.

## Рабочий процесс на этапе

1. Выбрать текущий майлстоун из чеклиста.
2. Разбить на мелкие шаги (функция/тип + тест).
3. Реализовать в ядре → прогнать `swift test` → зафиксировать.
4. Визуальные/хост-части — проверить на машине с Xcode/в System Settings.
5. Обновить статус майлстоуна в README.
