# Правила разработки проекта: strange-attractor-screensaver

> Стек утверждён: `.appex`, SceneKit, NSExpression, Swift, без внешних зависимостей.
> Среда разработки: macOS 26 arm64; установлены Command Line Tools (swift/SPM), полного Xcode нет → сборка `.appex` выполняется в Xcode отдельно.

## Локальный запуск

### Чистое ядро (SPM) — работает из папки проекта
Инициализация (M0, делаем один раз):
```bash
# создать пакет ядра (например в подкаталоге `Core/`)
cd Core && swift package init --type library
# либо создать Package.swift в корне и указать пути
```
Прогон тестов (ядро):
```bash
swift test                                  # из каталога пакета
swift test --filter Lorenz                  # выборочно
swift build                                 # сборка без тестов
```
SPM работает в этой среде — основная проверка логики происходит именно здесь, без Xcode.

### Визуализация (демо-приложение, AppKit + SceneKit)
- Собирается в Xcode (таргет демо-приложения), либо из командной строки, если Xcode будет установлен.
- Запуск демо: выбор манифеста, ручные параметры → окно с рендером.

### Хост-скринсейвер (`.appex`) — требует Xcode
- Таргет «Screen Saver» (`.appex`), главный класс `ScreenSaverView`.
- Проверка: System Settings → Screen Saver → выбрать наш → Preview/Test.
- В этой среде без Xcode эта часть собирается только на машине с Xcode.

## Тестирование (стратегия)

Правило: **ядро тестируется автоматически, рендер/хост — вручную.**

1. **Юнит-тесты ядра (SPM, `swift test`)** — основной уровень:
   - Декодинг конфига: валидная фикстура, отсутствующие поля, битые числа, неизвестные ключи → корректная ошибка.
   - Математика: RK4 против Эйлера, сходимость при уменьшении шага; эталонные численные траектории (например, известное поведение Лоренца/инварианты).
   - Парсинг формул NSExpression: подстановка параметров, синтаксические ошибки выражений.
   - Случайный выбор: выборки параметров строго внутри `[min, max]`, воспроизводимость по seed.
2. **Визуальная проверка** (демо-приложение, вручную): картинка траектории, вращение камеры, смена цвета следа, формулы/параметры в углу.
3. **Смоук на реальном скринсейвере** (`.appex`, вручную): Preview и Test в System Settings, старт/остановка, случайность запусков.

Перед коммитом обязателен зелёный `swift test` (для шагов, затрагивающих ядро).

## Код-стайл и конвенции

- **Язык кода:** Swift. Идентификаторы и комментарии в коде — на английском (`state`, `step`, `AttractorEngine`).
- **Документация и общение:** README, memories — на русском.
- **Модульность:** чистое ядро (SPM) отдельно от UI-рендера и хост-оболочки. Логика не зависит от рендера → тестируемость.
- **Тесты рядом с кодом:** для каждого публичного символа ядра есть покрытие.
- **Публичные API** — с `///`-комментариями (назначение, параметры).
- **Зависимости:** не добавляем внешние без необходимости; предпочтение Apple-фреймворкам.
- **Naming:** типы — существительные (`ODESolver`, `TraceRenderer`), функции/методы — глаголы (`step`, `select`, `render`).

## Git-практика

- Атомарные коммиты: один логический шаг = один коммит, сообщение по смыслу (тип: описание), на английском.
- Каждый майлстоун завершается зелёными тестами и (если нужно) отдельным коммитом.
- Работа ведётся в ветках по этапам, мёрдж в `main` после зелёных тестов.
- `swift test` перед коммитом ядра.

## Итеративный чеклист (майлстоуны)

Принцип: **маленькие итерации**, каждый шаг завершается работающим состоянием и зелёными тестами. Порядок выстроен от тестируемого ядра к Xcode-хвостам.

- **M0 — Фундамент.** SPM-пакет ядра; тесты поднимаются (`swift test` зелёный); git-практика.
- **M1 — Модель данных и конфиг.** `AttractorDescriptor`, `Parameter`, `SimulationHyperparameters` (Codable); пример `attractors.json` (Лоренц/Рёсслер/Томас); тесты декодинга.
- **M2 — Математическое ядро.** `AttractorModel` (NSExpression-формулы), `ODESolver` (RK4 + Euler), `AttractorEngine` (поток точек); численные тесты.
- **M3 — Выбор.** `Randomizer` (случайный аттрактор/параметры/гиперпараметры), `DebugConfig` (ручные параметры); тесты диапазонов и seed-воспроизводимости.
- **M4 — Визуализация в демо-приложении.** SCNView, `TraceRenderer`, `CameraController`, запуск/остановка, ручные параметры; визуальная проверка.
- **M5 — Хост `.appex`.** Таргет Screen Saver, `ScreenSaverView`, подключение ядра, вывод формул/параметров в углу; проверка в System Settings.
- **M6 — Полировка.** Производительность, крайние случаи (деление на ноль/нестабильные параметры), упаковка и документация.

Статус отмечаем в README (раздел «Дорожная карта»): ⏳ / в работе / ✅.

## Рабочий процесс на этапе

1. Выбрать текущий майлстоун из чеклиста.
2. Разбить на мелкие шаги (функция/тип + тест).
3. Реализовать в ядре → прогнать `swift test` → зафиксировать.
4. Визуальные/хост-части — проверить на машине с Xcode/в System Settings.
5. Обновить статус майлстоуна в README.
